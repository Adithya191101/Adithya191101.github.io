Perception-Driven reArm B601-DM Pick-and-Place

An end-to-end Isaac ROS manipulation stack that detects a bottom-up soup can, estimates its 6-DoF pose, reconstructs a two-camera obstacle map, plans the carried object around a hard wall, grasps through physical finger contact, rotates the can upright, and releases it under gravity.

August 2026
reArm B601-DM
Isaac Sim 5.1 + Isaac ROS 4.5
Simulation / Physical AI
View on GitHub Watch Demo

Project Overview

This project adapts NVIDIA's Isaac for Manipulation reference architecture to the Seeed Studio reArm B601-DM. It closes the complete perception-to-action loop in simulation: camera observations create the object pose and collision map, the planner produces robot motion, and PhysX contact determines whether the grasp and release actually work.

The repository is a source-only overlay rather than a copy of NVIDIA and Seeed trees. External repositories are pinned to immutable commits, one reviewable patch carries the workflow integration, and bootstrap scripts reconstruct the complete environment, models, and GPU-specific TensorRT engines locally.

Project Goal

Demonstrate a collision-aware pick-and-place task in which perception supplies the object pose, mapped depth supplies the obstacle geometry, cuMotion plans both the robot and carried-can volume, and the simulated gripper succeeds through contact physics instead of a hidden weld or object teleport.

Perception-to-Action Architecture

Isaac Sim RGB-D cameras → Grounding DINO detection → FoundationPose 6-DoF pose → axial-pose canonicalization → grasp goal set
two depth cameras → robot segmentation → nvblox ESDF → cuMotion + MoveIt → ROS 2 control + physical gripper

Perception and 6-DoF Pose

Open-Vocabulary Detection

  • Grounding DINO locates the prompted soup-can class
  • Detection score and bounding box are projected into the observer view
  • Fail-closed connectivity checks require the detector action server

FoundationPose

  • RGB, depth, intrinsics, ROI, and the textured can mesh produce a 6-DoF pose
  • Projected object axes make pose direction visible in the recording
  • Axial sign handling preserves top-up versus bottom-up orientation

Camera Contract

  • The calibrated static scene camera is the pose-estimation source
  • Camera frame IDs and timestamps are kept consistent through ROS 2
  • The wrist RGB-D stream remains separate from the static-camera pose chain

Mapping and Obstacle Avoidance

Two fixed depth views are synchronously throttled, segmented with the robot model, and fused by nvblox. The resulting ESDF is the live world representation used by cuMotion. A visible, collidable transfer wall also has a hard geometric safety shell so contact or insufficient clearance fails the task rather than becoming a visual-only defect.

1

Observe

Publish synchronized RGB, optical-Z depth, CameraInfo, TF, and joint state from Isaac Sim across DDS.

2

Remove the robot

Use the current robot geometry to mask arm pixels from both mapping depth streams so the manipulator does not become a moving obstacle to itself.

3

Build the ESDF

Fuse the two masked views in nvblox and expose distance-to-obstacle information to the GPU planner.

4

Plan the carried volume

cuMotion evaluates the robot collision spheres and the logically attached can volume, routing the payload around the wall before execution.

Physical Grasp and Release

Contact-Driven Closure

  • Dynamic can with gravity and rigid-body contact
  • Force-limited prismatic jaw drives
  • Single-actuator mimic constraint tuned and verified
  • Millimetre-scale contact generation around the fingers

Orientation-Aware Transfer

  • Multiple grasp candidates are generated from the detected axial pose
  • The bottom-up can is rotated consistently into an upright placement
  • The behavior tree coordinates approach, close, lift, transfer, and lower

Honest Release

  • No kinematic object pose writes during the grasped motion
  • Planner attachment represents collision volume, not a physics weld
  • Opening the fingers above the destination lets gravity finish placement

Engineering Highlights

Reconstructable Overlay

  • Four upstream trees pinned to immutable commits

  • Checksummed vendor USD and generated robot files

Reproducible Runtime

  • Dockerized ROS 2 Jazzy and Isaac ROS 4.5 workflow

Fail-Closed Gates

  • Connectivity, models, source pins, build, and overlay checks
  • Wall contact and clearance monitored during execution
  • Incomplete behavior-tree goals return a nonzero result

Scope and Transfer to Hardware

The demonstrated result is simulation-only. The repository includes a separate real-camera extrinsics profile, but it intentionally remains unavailable until physical hand-eye calibration is completed. Real deployment also requires robot-side safety validation, measured gripper contact parameters, camera calibration, and launch-profile verification on the physical B601-DM.

Model weights, NVIDIA containers, and TensorRT engines are not redistributed. The bootstrap path requires explicit acceptance of the applicable third-party licenses and builds hardware-specific engines on the target GPU.
