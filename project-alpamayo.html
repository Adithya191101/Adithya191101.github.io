Reasoning VLA in Closed-Loop AV Simulation

Reproduced NVIDIA Alpamayo 1.5 - a 10B-parameter reasoning Vision-Language-Action model - inside AlpaSim on a Hyperstack H100. Built an end-to-end open-source reproduction guide and a 15-page study companion on the architecture.

Project Overview

Self-driving cars do well on common scenarios and struggle on the long tail - construction zones, ambiguous merges, pedestrians stepping out from between parked cars. NVIDIA's Alpamayo family addresses this with a reasoning Vision-Language-Action model that, alongside its trajectory prediction, emits a written chain-of-causation explaining what it saw and why it chose the action it did.

This project reproduces Alpamayo 1.5 end-to-end on real driving scenes. The model runs inside AlpaSim, NVIDIA's closed-loop simulator, on neural reconstructions of recorded drives from the NuRec dataset. The artifacts include verified setup scripts, demo videos, a curated showcase, and a 15-page study guide on the underlying architecture.

Project Goal

Get NVIDIA Alpamayo 1.5 running on real driving scenes in closed-loop simulation, extract and analyze its chain-of-causation reasoning traces, and publish a complete open-source reproduction guide so others can do the same in under an hour.

The Three-Piece Stack

Understanding Alpamayo 1.5 requires understanding the two other open NVIDIA components it depends on, and the simulator that exercises it on real scenes.

Alpamayo 1.5 - The Driver

  • 10B-parameter VLA model
  • 4 camera views in, trajectory + reasoning out
  • Diffusion-based action decoder (2.3B params)
  • Closed-loop benchmark: 0.81 on AlpaSim

Cosmos Reason 2 - The Backbone

  • 8B reasoning VLM for physical AI
  • ViT + dense LLM transformer
  • Post-trained from Qwen3-VL-8B-Instruct
  • 256K context for multi-camera history

AlpaSim - The Testbed

  • Microservices via docker-compose
  • Runtime + Driver + Physics + SensorSim
  • Plays NuRec USDZ scene reconstructions
  • Emits rollout.asl binary trace + mp4 video

Implementation Approach

The reproduction took several iterations. The non-obvious lesson up front: most cloud GPU providers cannot host AlpaSim because their container-based pods block the syscalls Docker needs to register image layers. Hyperstack's KVM VMs work; RunPod doesn't.

1

Provider selection

Verified empirically that RunPod's standard pods block the unshare() syscall via seccomp, so Docker image-layer registration fails. Switched to Hyperstack's KVM virtual machines (full root, full Docker support) at H100 80GB PCIe.

2

Automated VM bootstrap

Wrote a single-shot bootstrap script that disables apt-daily.timer (otherwise unattended-upgrades holds the dpkg lock for 25 min on a fresh Ubuntu image), installs Docker + NVIDIA Container Toolkit, sets up uv + Rust, clones AlpaSim, and pre-builds the alpasim-base image serially to avoid parallel-build disk explosion.

3

Storage layout fix

AlpaSim's docker-compose builds blow past a 100 GB boot disk. Solution: symlink /workspace to Hyperstack's 750 GB ephemeral SSD, pre-configure /etc/docker/daemon.json to use that path as data-root, and relocate /var/lib/containerd there.

4

Gated-model access

Alpamayo 1.5 internally loads nvidia/Cosmos-Reason2-8B as its reasoning backbone - both are HuggingFace-gated and must be approved separately, along with the NuRec scenes dataset.

5

Scene curation

Wrote a filter that scans NuRec's per-scene labels.json metadata for visual cleanliness (clear weather, dry surface, daytime) plus reasoning interest (intersection + pedestrian crossing, construction zone, lane changes). Ranked the 824 labeled scenes and ran the top candidates.

6

Reasoning extraction

Parsed the binary rollout.asl protobuf log to extract per-timestep reasoning text from the driver's debug field, coalesced consecutive duplicates, and surfaced the unique reasoning chains across each 20-second run.

7

LinkedIn-ready compositor

Built an ffmpeg pipeline that composites AlpaSim's DEFAULT and REASONING_OVERLAY layouts into a single 1920×1080 video - BEV map + camera + reasoning banner + trajectory chart in one frame.

Sample Chain-of-Causation Reasoning

The model emits a short causal explanation alongside every trajectory. These are pulled directly from the rollout.asl log of the construction-zone scenario:

"Stop to yield to the pedestrian in the crosswalk since they are walking across our path"

"Slow down to create a gap for a merge to the left because our current right lane narrows ahead while a bus is occupying the left lane, blocking an immediate merge"

"Nudge left due to the stopped truck blocking the right side of our lane"

"Turn right because the one-way sign indicates right only"

Each reasoning chain identifies the action, names the cause(s) it observed in the scene, and (often) sketches the plan that follows. The model emitted 30+ distinct reasoning chains in a single 20-second scenario.
